1. **[P2] 浮動小数点のビン割り当てを、表示・フィルタ判定と同じ境界に合わせる**

   対象: [`histograms.py:220–223`](https://github.com/ribuka/flat-pca/blob/bd333c9276b787bc28f066b3b533477b2922991a/src/flat_pca/webui/datatable/histograms.py#L220-L223)

   `_bin_index` は境界配列を使わず、別の算術式を `floor()` してビンを決めるため、丸め誤差で境界上の値が左隣のビンに入ります。例えば `x = [0.1, 0.18, 0.5]` では、`0.18` が本来の `[0.18, 0.20)` ではなく `[0.16, 0.18)` に数えられます。下限を `0.18` にすると `apply_state` の表示行には `0.18` が残る一方、この値を数えたビンは `in_filter=False` になります。通常の小数値でも件数とフィルタ表示が食い違うため、生成した境界に基づいて所属を判定し、境界上の値と下限が一致するケースをテストしてください。

2. **[P2] 有限な Float64 値でもオーバーフローしない境界・インデックス計算にする**

   対象: [`histograms.py:191–192`](https://github.com/ribuka/flat-pca/blob/bd333c9276b787bc28f066b3b533477b2922991a/src/flat_pca/webui/datatable/histograms.py#L191-L192)、同ファイル220–223行

   入力の NaN・無限大を除外しても、`maximum - minimum` と `span * index`、インデックス計算の乗算自体がオーバーフローします。`x = [-1e308, 0.0, 1e308]` はすべて有限ですが、境界が NaN になり、`column_histograms` が `InvalidOperationError`（NaN の Int128 への変換失敗）を送出します。number メタデータはこれらの値を Float64 として受け入れるため、ヒストグラムを常時有効にした `/catalog/files` が表示できなくなります。`[0.0, 1e307, 2e307]` でも境界に `inf` が混じり、中央の値が最後のビンに誤集計されます。境界の補間と所属判定を中間演算のオーバーフローに耐える方法に変更し、有限値の広い範囲を検証してください。

3. **[P3] 整数ビン幅の切り上げを整数演算だけで行う**

   対象: [`histograms.py:168`](https://github.com/ribuka/flat-pca/blob/bd333c9276b787bc28f066b3b533477b2922991a/src/flat_pca/webui/datatable/histograms.py#L168)

   `/ MAX_BINS` が一度 float に変換するため、64 bit の広い範囲では `math.ceil` の前に精度が失われます。`integer_bins(0, 2**64 - 1025)` では幅が本来の `922337203685477530` より小さい `922337203685477504` になり、「20本以内」の仕様に反して21本返ります。この範囲は対応対象の UInt64 に収まります。`(maximum - minimum + 1 + MAX_BINS - 1) // MAX_BINS` のように整数演算で切り上げ、64 bit の端付近で割り切れない範囲もテストしてください。
